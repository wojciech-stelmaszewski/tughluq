# Watch panel — RL observation (2D)

**Session start:** 2026-09-15_10-38  
**Status:** implemented  

## Goal

Add a **second page**: a flat admin panel that will later track reinforcement-learning runs while we search for an optimal Zombie Hunt policy. **No 3D on this page.**

This slice is the **observation surface + snapshot model**. It is not a trainer. The game loop (pairing, duels, infection, 20-round verdict) does not exist yet, so there is nothing real to train against.

## Why not train yet

A policy that plays cards, uses Shotgun / Vaccine, and chooses opponents needs Phases 2–5. Shipping a neural net or a gym loop now would be speculative (YAGNI). The panel must still look like a run monitor: generation, round, 64 player rows, and a few aggregate numbers — filled from a **dealt tournament snapshot**, with run counters starting at generation 1 / round 0 (pre-play).

| Path | Page | Renderer |

Routing: read `window.location.pathname` in `main.tsx`. No router library. A text link on each page switches views. Vite already serves the SPA; add `appType: 'spa'` fallback so `/watch` reloads.

## Tournament deal (64)

Canon: **4 groups × 16**. Keep the existing `deal()` for one group (3D lab stays 2–16).

Add `dealTournament(params, seed)` that calls `deal()` four times with derived seeds and remaps ids:

- `Player 01` … `Player 64`
- `group: 1..4`
- **1 Zombie per group** (already true inside `deal()`)
- Vaccines: `vaccinesPerGroup` (default 2) — same meaning as today’s vaccine count, applied per wing

Do **not** raise `MAX_PLAYERS` used by the 3D HUD. A 64-seat WebGL wing is out of scope.

## Snapshot model

One type, e.g. `WatchSnapshot`, owned by `src/watch/` (or `src/rl/` — pick `watch` so the folder matches the route):

| Field | Source this slice |
| --- | --- |
| `generation` | 1 (editable later; display now) |
| `episode` | 1 |
| `round` | 0 (deal only; later 1–20) |
| `seed` | tournament seed |
| `players[]` | 64 rows from `dealTournament` |
| `stats` | derived: humans, zombies, eliminated, vaccines held, shotguns held, mean regular-card count |

Per player row:

- id, display name, group
- faction: `human` \| `zombie` (from holding a Zombie card; later also `eliminated`)
- regular card count
- flags: shotgun / zombie / vaccine
- last action: `—` until a trainer exists
- return / fitness: `—` until a trainer exists

Derive rows with a small pure function `snapshotFromTournament(deal, counters)` — no React inside.

## UI (KISS)

One scrollable page, same IBM Plex / dark lab tokens, **not** the floating HUD overlays.

1. **Top bar** — title, generation, episode, round, seed, human/zombie counts. Link back to `/`.
2. **Stat chips** — 6–8 numbers, no chart library.
3. **Player table** — all 64 rows visible without paging (filter by group optional, default show all). Dense rows so 64 fit on a desktop with scroll.

No play/pause trainer buttons that pretend a loop exists. No TensorFlow, no worker, no persistence.

## CSS

`html, body, #root { overflow: hidden }` is for the 3D lab. Scope that to `.lab-root`. Watch page uses `.watch-root` with `overflow: auto` so 64 rows can scroll.

## Out of scope

- 64 seats in WebGL

## Critical review

- **KISS:** second component + pathname switch + compose four existing deals.
- **YAGNI:** counters and empty action/return columns, not an RL engine.
- **SRP:** `dealTournament` builds the field; `snapshotFromTournament` shapes watch rows; React only renders.
- **DRY:** reuse `deal()`, types, and `playerHasKind`. Do not duplicate card math in JSX.
