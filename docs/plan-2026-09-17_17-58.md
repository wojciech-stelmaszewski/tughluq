# Plan — RL stage B: linear scorer + evolution strategy (2026-09-17_17-58)

Status: stage B implemented.

## Need

Stage A can inject a policy and measure it. It cannot search. The next step is a trainer
that produces a **new** `Policy` — not a pick among `randomLegal` / `aggressive` /
`conservative` — and reports whether it beats the Stage A bar.

Bar, from [baselines-2026-09-16.md](./baselines-2026-09-16.md), seed 1, 50 episodes,
8 vs 56 `randomLegal`: `aggressive` differential **+0.257**. A learned policy that cannot
beat that has learned nothing we could not have typed.

## What we train

Same seam as Stage A. Score each legal action, softmax, **sample** (not argmax — moves are
simultaneous, so play must be mixed).

Scorer is **linear**, not an MLP:

    score(action) = w · concat(encodeViewVector(view), encodeAction(play, view))

That is a few dozen weights. Enough to express “prefer Zombie”, “prefer small pile”,
“prefer shotgun late”. An MLP waits until the linear policy plateaus.

No autodiff. Evolution strategy: perturb `w`, evaluate, keep the elite.

## How fitness is measured

Unchanged from Stage A:

    fitness = clear rate of 8 candidate seats − clear rate of 56 reference seats
              (same match, same seed)

Reference starts as `randomLegal`. Every K generations, if the elite beats the current
reference, freeze the elite as the new reference (a tiny league, not 63 frozen random bots
forever).

Also log, and do not maximize: end-of-match zombie share, shotgun uses, vaccine uses,
when all 64 seats run the elite (population dashboard). Mass infection is a **hypothesis**,
not a pass condition — pairing is still random and faction is hidden, so “convert everyone”
may not be the learned attractor.

## What we do not build

- No PPO, no replay buffer, no Python.
- No belief model of who is a zombie.
- No pairing as a player action.
- No reward shaping.
- `/watch` does not run the trainer. CLI trains; `/watch` can load a saved weight file
  later. Filling `generation` / `fitness` on the snapshot is optional and only if it stays
  a one-line pass-through from `MatchState`.

## Success

1. `npm run train` runs N generations and writes `weights.json`.
2. Elite vs `randomLegal` differential is **above** `aggressive`’s +0.257, or we record
   that linear ES plateaued below the bar (still a result).
3. A unit test: `scoredPolicy(weights)` is a `Policy`; same seed + weights ⇒ same match.
4. Tests from Stage A still pass.

## Review against the core principles

**KISS.** Linear scorer, softmax sample, existing `evaluateDifferential`. No MLP until
this plateaus.

**YAGNI.** No PPO, no watch-page training loop, no pairing UI.

**SRP.** Trainer in `src/rl/`. `match.ts` unchanged except perhaps copying generation
into state if the CLI sets it.

**DRY.** Reuse `encodeView` / `encodeAction` / `evaluateDifferential` / `bindSeating`.
