# Plan — reinforcement learning: policy interface, baselines, trainer (2026-09-16_17-49)

Status: stage A implemented.

## Need

Phase 7 asks for a policy that plays a full 20-round match unattended. Today the only policy is
`pickRandomPlay`, a private function buried inside `resolveDuel` (`src/game/match.ts:168`). Nothing
can be injected, nothing can be measured, and there are no tests, so a learned agent would be
indistinguishable from an agent exploiting a rules bug.

## What kind of problem this is

The reward is **individual** — a player clears by standing on the larger side after round 20 — but
the game is **not** single-agent and **not** zero-sum:

- Many players clear at once. A 40–24 split means 40 winners.
- A player's payoff depends on the global faction split, which no single decision controls.
- Training one agent against 63 random bots yields a best response to randomness, which collapses
  as soon as the opponents improve. The environment is non-stationary.

So: individual reward, self-play training. One match yields 64 trajectories.

Structural facts that shape the design:

- At most **one decision per player per round**: a `TablePlay` (suit + non-empty subset of that suit
  + optional special). Pairing and the theft draw belong to the environment, not the player.
- Moves inside a duel are **simultaneous**, so optimal play is mixed, not deterministic.
- Number cards are both ammunition and hit points: a bigger pile wins more duels but exposes a
  better card to theft, and an empty pile is elimination.
- Horizon ≤ 20 decisions, reward only at the end. Sparse but very short.
- Infection is **private**. A player knows their own faction (they hold, or do not hold, a Zombie
  card). They do **not** know whether the opponent is infected, and they do **not** know the living
  zombie share. They do know how many players are still in the game. Hand *contents* of others stay
  hidden. `/watch` remains omniscient (dealer view); that leak must not enter `PlayerView`.

  `getLegalActions` offers Vaccine whenever it is held (never on self). A miss is spent, same as
  before. Shotgun is always legal and is a guess: kill if zombie, waste if human.

## Observation (limited information)

The agent does **not** see opponents' cards, opponent faction, or the global zombie share.
Feature vector, roughly 20 numbers:

- Own hand, per suit: count, sum, highest rank.
- Own specials: shotgun / zombie / vaccine held.
- Own infected flag, own regular-card count.
- Opponent: hand size only (not infected).
- Match: round / 20, living count. No zombie share.

## Action encoding

Do **not** use a fixed-size action head. The legal set varies in size, so score each legal play with
a shared network and take a softmax over the legal set. Action features:

- Pile sum, pile size, highest rank in pile.
- Share of that suit committed, share of own regulars committed, regulars left after the play.
- Special played, one-hot: none / shotgun / zombie / vaccine.

One encoder serves both ES and PPO, and illegal actions are excluded by construction rather than
masked after the fact.

## Reward

Terminal only: `1` on GAME CLEAR, `0` on GAME OVER. No shaping in the first pass — shaping survival
would push the agent toward hoarding, which is exactly one of the strategies we want to *test*, not
assume.

Open rules question for [rules-audit.md](./rules-audit.md): `majorityVerdict`
(`src/game/match.ts:370`) can return an exact tie, where neither side is larger. Score it as `0` for
everyone until the rule is settled.

## Fitness must be differential

The trap specific to this game: if every seat runs the same policy, the absolute clear rate is
decided by the match-level faction split, not by skill. Everyone wins together or loses together, so
the signal drowns in shared noise.

Measure instead: seat the candidate in a **minority of seats** (e.g. 8 of 64) among a reference
population, and score

    fitness = clear rate of candidate seats − clear rate of reference seats (same match, same seed)

This pairs the candidate against the coordination outcome it actually faced and cuts the variance
that otherwise dominates.

## Stages

**A — plumbing (this plan's tasks).** Policy interface, `getLegalActions`, headless Node runner,
rules tests, hand-written baselines, differential evaluation harness. No learning.

**B — evolution strategy.** Small MLP scorer, perturb-and-select against a reference league. Fills
the `generation` / `episode` / `fitness` placeholders that already exist in `MatchState` and the
`/watch` snapshot.

**C — PPO.** Same observation and action encoder, swapped optimiser. Compare against the ES result.

## Validation target

This game has a known answer: the canon solution is to convert everyone. If training works, the
population should discover mass infection on its own. If a converged population still plays
scattered, the reward or the self-play loop is wrong.

## Review against the core principles

**KISS.** One encoder, one policy interface, terminal reward, no shaping. ES before PPO because it
needs no autodiff dependency.

**YAGNI.** No replay buffer, no distributed workers, no Python bridge, no belief model of who is a
zombie. The agent simply does not receive that bit. Stage A ships zero learning code.

**SRP.** Rules stay in `src/game/`. Policies, features and the trainer live in a new `src/rl/`.
`match.ts` learns nothing about neural networks; it only gains the seam to ask a policy for a play.

**DRY.** Deliberately accepted: the baselines will each re-derive legal plays through the same
`getLegalActions`, and no abstraction is introduced to share their heuristics.
