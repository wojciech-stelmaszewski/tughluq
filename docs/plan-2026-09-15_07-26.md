# Phase 1 Plan — Zombie Hunt Deal Simulation

**Session start:** 2026-09-15_07-26  
**Updated:** 2026-09-15_07-29 (canonical Fandom rules pasted by the user)  
**Status:** implemented  
**Scope:** deal only (no turns, no duels, no infection resolution)

This document describes the first implementation slice of a browser-based, turn-based simulation of *Zombie Hunt* (Alice in Borderland, Netflix). Later phases are listed in [plan.md](./plan.md).

## 1. Goal

Build a local web app that:

1. Accepts **player count** and **vaccine count** as deal parameters.
2. Deals a legal opening hand to every player according to the Netflix rules summarized below.
3. Renders that deal as a cinematic 3D scene in the browser (WebGL).
4. Starts locally with a single Makefile target.

No gameplay loop in this phase. The product of Phase 1 is a **beautiful, repeatable deal**.

## 2. Source of rules

Canonical text is the Fandom page *Zombie Hunt (Netflix)*, pasted by the user. Full extract: [rules.md](./rules.md).

Phase 1 encodes the **opening deal for a single group** (one of the four wings):

| Item | Rule |
| --- | --- |
| Regular cards | Each player receives **7** standard playing cards (French deck: suits ♠ ♥ ♦ ♣, ranks A–K). |
| Shotgun | Each player receives **exactly 1** Shotgun card. |
| Zombie | **Exactly 1** Zombie card is given to one random player (one seed zombie per group). |
| Vaccine | **N** Vaccine cards, where N is a deal parameter, assigned to **N distinct random players**. A zombie may receive a vaccine (they cannot later use it on themselves — not simulated yet). |
| Extra decks | `playerCount * 7` regular cards are drawn from as many shuffled 52-card decks as needed. |
| Visibility | Phase 1 uses an **omniscient dealer view**: all hands are visible so the simulation can be inspected. |

Not parameters in Phase 1 (fixed, YAGNI):

- Shotgun count per player = 1
- Initial zombie count = 1
- Regular cards per player = 7
- Number of groups / tables = 1
- Round count = unused

## 3. Deal parameters

```ts
type DealParams = {
  playerCount: number;   // inclusive range: 2–16
  vaccineCount: number;  // inclusive range: 0–playerCount
};
```

Validation (fail before shuffle):

- `playerCount` is an integer in `[2, 16]`.
- `vaccineCount` is an integer in `[0, playerCount]`.

Rationale for the 16 cap: one canon group is 16 players; more than that around a single table becomes unreadable. Multi-group (4 × 16) is a later phase.

## 4. Deal algorithm (pure, deterministic given a seed)

Keep deal logic in a framework-free module. No Three.js, no React.

```
seed = random or user-provided (optional UI field; default: Date.now())
rng  = seeded PRNG (mulberry32 — tiny, enough)

regularPool = concat(ceil(playerCount * 7 / 52) full 52-card decks)
shuffle(regularPool)

for each player i in 0..playerCount-1:
  hand.regular = take 7 cards from regularPool
  hand.shotgun = 1
  hand.zombie  = false
  hand.vaccine = false

pick 1 distinct player index → zombie = true
pick vaccineCount distinct player indices → vaccine = true
```

Output is a `Deal` value object the renderer can play back:

- `params`, `seed`
- `players[]` with `id`, `displayName` (`Player 01` …), `cards[]`
- each card: `{ id, kind: 'regular' | 'zombie' | 'shotgun' | 'vaccine', suit?, rank? }`

Re-deal with the same seed must produce the same hands. Re-deal with a new seed reshuffles.

## 5. Technology

Chosen for KISS and a high visual ceiling without writing raw GLSL by hand:

| Layer | Choice | Why |
| --- | --- | --- |
| App shell | Vite + React 19 + TypeScript | Fast local loop, typed UI |
| WebGL | Three.js via `@react-three/fiber` + `@react-three/drei` | Idiomatic React + WebGL; cards, lights, animation |
| State | Local React state + one `useDeal()` hook | One screen, no global store yet |
| Deal engine | Pure TS in `src/game/` | Testable without the canvas |
| Dev server | Vite on port 5173 | Makefile `make dev` |

Explicitly **not** in Phase 1: Redux/Zustand, routing, backend, Docker, tests beyond a tiny pure-function check if time allows, physics engine, multiplayer.

## 6. Visual direction

Tone: **National Institute of Virus Research** — sterile, bright, clinical. White floors, cool fluorescent / LED strips, a hint of cyan from lab signage. Not a dark neon nightclub.

Scene (single view, one wing / one group):

1. White rectangular mini-game table inspired by the gallery (clean slab, subtle arch suggestion, a small metallic dome in the center as set dressing — it does **not** fire in Phase 1).
2. Players as simple stands / nameplates around the table (no full character models — YAGNI). For 2–16 seats, use two long sides if a rectangle reads better than a circle.
3. A deck near the dome. Deal animation: cards fly from the deck to each seat in seating order, then fan.
4. Regular cards: readable French-deck faces (suit + rank).
5. Special cards: distinct faces, close to the named props
   - Zombie — dark / biohazard
   - Shotgun — metallic / spent-brass
   - Vaccine — clinical white-cyan
6. After the deal, a three-quarter camera. User can orbit/zoom (drei `OrbitControls`, damped).
7. HTML overlay (React, not WebGL) for parameters, seed, **Deal**, **Redeal**, and a compact legend (humans / zombie / vaccine holders).

Motion:

- Staggered deal (~40–60 ms between cards).
- Ease-out on land; slight overshoot is enough.
- No lasers, no elimination device, no particle blood.

Readability over spectacle: at 16 players the fan must still show special cards. Special cards sit slightly raised and tinted.

## 7. UI (deal controls)

Minimal overlay, top or left:

- Number input: Players (2–16)
- Number input: Vaccines (0–players)
- Optional: Seed
- Primary button: **Deal**
- Secondary: **Redeal** (new seed)
- Status line: `16 players · 1 zombie · 3 vaccines · seed 18421`

Default on first load: **16 players, 2 vaccines** (16 is a canon group). Seed is random unless typed.

No login, no persistence beyond the current page.

## 9. Makefile (local dev)

```make

install:
	npm install

dev: install
	npm run dev -- --host 127.0.0.1 --port 5173

build: install
	npm run build

preview: build
	npm run preview -- --host 127.0.0.1 --port 5173

clean:
	rm -rf node_modules dist
```

`make dev` is the only command required to run the app locally. Node.js 20+ is the documented prerequisite.

## 10. Critical review (KISS / YAGNI / SRP / DRY)

| Principle | Decision |
| --- | --- |
| KISS | One scene, one deal function, no store, no router, no Docker. R3F instead of raw WebGL. |
| YAGNI | No turn engine, no pairing, no AI, no 4-group tournament, no character models, no sound unless it is a single optional whoosh. |
| SRP | Deal math is pure TS. Renderer consumes a `Deal`. Controls only emit `DealParams`. |
| DRY | One card type + `kind` discriminant. One shuffle. Regular faces generated from suit×rank, not 52 hand-authored textures (procedural canvas or simple SVG-on-canvas is enough). |

Rejected alternatives:

- Raw WebGL / custom shaders for cards — too much work for Phase 1.
- Babylon.js — extra stack for no gain here.
- Simulating 64 players / 4 rooms now — unreadable and unused.
- Making zombie count a third parameter — you specified only players and vaccines.

## 11. Assumptions to confirm

Please accept or correct these before implementation:

1. **Single group only** in Phase 1 (one wing / one table, one seed zombie). Canon 4×16 comes later.
2. **Omniscient view** — every hand face-up after the deal.
3. **Player names** are generated (`Player 01` …), no roster editor.
4. **Seeded RNG** so a deal can be reproduced.
5. **Procedural card faces**, not scanned Netflix prop art (copyright and clarity).
6. **English** in code, comments, and docs; UI labels in English as well.
7. **Node + npm + Makefile** only — no Docker in Phase 1.
8. **Shotgun / Zombie / Vaccine sit on top of the seven number cards**, not inside those seven slots.
9. **Look:** bright sterile institute, not dark neon. White table + unused elimination dome as set dressing.

## 12. Done when

- `make dev` serves the app on `http://127.0.0.1:5173`.
- Changing player/vaccine counts and clicking Deal produces a new legal deal and a visible 3D deal animation.
- Same seed → same hands.
- Special cards are visually distinct and countable against the legend.
- No turn / duel / infection code is present.

## 13. Out of scope (this phase)

Turns, table pairing, suit-match duels, infection, shotgun kill, vaccine cure, 20-round scoring, lasers / GAME OVER, audio design, persistence, tests suite, CI, Docker.
